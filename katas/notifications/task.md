## Задача

Реализуйте два класса, независимо удовлетворяющих контракту `Notifier`
из `base.py` (файл защищён — не редактируется, тесты пересобираются
из шаблона):

```python
class EmailNotifier:
    def send(self, message: str, recipient: str) -> bool: ...


class SmsNotifier:
    def send(self, message: str, recipient: str) -> bool: ...
```

Сами классы кладите в `solution.py` рядом.

## Требования к поведению

- `send("", recipient)` — бросает `ValueError`;
- `send(message, "")` — бросает `ValueError`;
- на непустых `message` и `recipient` — возвращает `True`.

Реальная отправка ничего никуда не шлёт — здесь важен контракт, а не
интеграция с почтовым сервером.

## Зачем

Один и тот же тест ниже прогоняется на обоих классах: если оба реализуют
контракт корректно, они взаимозаменяемы для любого кода, который зависит
только от `Notifier`, а не от конкретного класса. Это Dependency
Inversion в миниатюре — вызывающий код работает с абстракцией.
