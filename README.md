# Задание 1. OOP-абстракции и контракты (SOLID)

Курс «Программная инженерия», Политех, осень 2026.

Полезные материалы по SOLID и типизации — в [МАТЕРИАЛЫ.md](МАТЕРИАЛЫ.md).

## Зачем это задание

Дальше в курсе — Students API и Auth-сервис, где код обязан быть
разложен на слои (api/service/repository) и зависеть от абстракций,
а не от конкретных классов. Здесь те же принципы разбираются на
пяти маленьких, никак не связанных друг с другом примерах, без HTTP
и без базы данных — чтобы сама идея не тонула в инфраструктуре.

В каждой кате: `task.md` описывает контракт и класс(ы), которые нужно
реализовать в `solution.py`. Тесты уже написаны — их не нужно (и не
получится) подгонять под своё решение: часть файлов в `katas/`
защищена и восстанавливается из шаблона перед прогоном CI (см. ниже).

## Каты

Нужно сделать **все пять**:

| Ката | Принцип | Задание |
|---|---|---|
| notifications | (разминка) реализация интерфейса | [task.md](katas/notifications/task.md) |
| shapes | Liskov Substitution | [task.md](katas/shapes/task.md) |
| discounts | Open/Closed | [task.md](katas/discounts/task.md) |
| devices | Interface Segregation | [task.md](katas/devices/task.md) |
| payment | Dependency Inversion | [task.md](katas/payment/task.md) |

Single Responsibility здесь отдельной каты не получает — его смысл
лучше виден на целом сервисе, а не на одном классе. Он разбирается в
конспекте и проверяется на ревью Students API/Auth-сервиса (слои
api/service/repository — это SRP на уровне модулей).

## Что защищено, а что — ваше

В каждой папке `katas/<ката>/`:

- `task.md` — условие, не редактируется;
- `engine.py` / `base.py` / `interfaces.py` (где есть) — готовый код
  преподавателя (контракт-интерфейс, иногда ещё и закрытый для
  изменений класс, который через этот интерфейс работает) — не
  редактируется;
- `solution.py` — **это пишете вы**;
- `NOTES.md` — только в `katas/shapes/`, тоже ваше.

CI перед прогоном тестов **перезаписывает всё, кроме `solution.py` и
`NOTES.md`**, из этого же репозитория по тегу `reference-v1` — то есть
подправить контракт или тест под своё решение не получится, даже если
отредактировать локальную копию.

## Установка

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh   # macOS/Linux
```

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"  # Windows
```

```bash
make install   # uv sync
make hooks     # pre-commit install
```

## Как проверить себя локально

```bash
make check
```

То же самое, что гоняет CI: `ruff`, `mypy`, затем `pytest` по эталонным
тестам всех кат. Пока solution.py не создан — тесты соответствующей
каты `SKIPPED`, это нормально.

```bash
make check-volume   # все ли 5 кат сделаны
```

## Как сдавать

1. Ветка `develop` → реализация всех пяти кат.
2. PR `develop → main`, запросить ревью у преподавателя.
3. Написать в общий чат курса, что отправили на проверку.
4. **PR с непройденными проверками не смотрится.**
5. После approve — переходим к заданию 2 (алгоритмы и структуры данных).
